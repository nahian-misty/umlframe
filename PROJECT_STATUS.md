# UMLFrame — Project Status Guide

_A plain-English map of the codebase: what each file does, what's finished, what's still missing, and what tech it's built on. Generated by reading the code directly (not just the design docs) so it reflects what's actually there._

---

## 1. What this project is

UMLFrame turns UML class diagrams into code, and turns code back into diagrams. Everything passes through one shared format called the **Unified UML JSON** — no part of the system talks to another part except through this JSON.

- **Forward pipeline (done):** draw a diagram → export as PNG → computer vision + OCR reads the image → Unified UML JSON → generate Python/Java/JS source code.
- **Reverse pipeline (not built yet):** paste in source code → parse it → Unified UML JSON → render as a Mermaid diagram.
- **Multi-user platform (done):** users register/log in, own multiple projects, each project stores one diagram.
- **Future addition (not built yet):** a second diagram type, Activity Diagrams (flowcharts with start/end/decision boxes), bidirectional the same way.

## 2. Tech stack

### Backend (Python 3.11+)
| Library | What it's for |
|---|---|
| **FastAPI** | Web framework — all `/api/*` HTTP endpoints |
| **Uvicorn** | ASGI server that runs FastAPI |
| **Pydantic v2** | Every data model (UML schema, request/response bodies) — no raw dicts |
| **SQLAlchemy** | ORM — talks to the database |
| **SQLite** | The actual database (`umlframe.db` file on disk). Configurable via `DATABASE_URL` env var, defaults to SQLite — see `backend/config.py` |
| **PyJWT** | Issues/verifies login tokens (bearer auth) |
| **bcrypt** | Password hashing |
| **Jinja2** | Templates that render generated source code |
| **OpenCV (`cv2`)** + **NumPy** | Image preprocessing and shape detection for the image→diagram pipeline |
| **pytesseract** | OCR (reads text out of detected shapes) — wraps the Tesseract OCR engine |
| **pytest, httpx, ruff, mypy** | Testing, linting, type-checking |

> Note: `cv2`/`numpy`/`pytesseract` are used in `backend/cv/` and `backend/ocr/` but aren't currently listed in `pyproject.toml`'s dependencies — worth adding if you rebuild the environment from scratch.

### Frontend
| Library | What it's for |
|---|---|
| **React 19** + **react-dom** | UI framework |
| **TypeScript** | Type safety (strict mode) |
| **Vite** | Dev server / build tool |
| **react-router-dom** | Routing between pages (`/`, `/login`, `/dashboard`, `/editor/:projectId`, etc.) |
| **html-to-image** | Exports the canvas as a PNG |
| **lucide-react** | Icon set |
| **ESLint + Prettier** | Linting/formatting |

### Database
**SQLite**, accessed through SQLAlchemy. Two tables: `User` and `Project` (`backend/db/models.py`). A `Project` row stores its diagram as a JSON blob validated against the Unified UML JSON schema before it's written.

## 3. File-by-file: Backend

### Entry point
- **`backend/main.py`** — creates the FastAPI app, sets up CORS, initializes the DB on startup, and registers the four route groups that currently exist: `auth`, `projects`, `codegen`, `image`.
- **`backend/config.py`** — environment-based settings (DB URL, JWT secret, token expiry, CORS origins).

### Auth & Projects (done — Milestone 8)
- **`backend/db/models.py`** — SQLAlchemy `User` and `Project` ORM models.
- **`backend/db/session.py`** — DB engine/session setup, `init_db()`, `get_db()` dependency.
- **`backend/services/auth_service.py`** — register, login, password hashing, JWT issuing.
- **`backend/services/project_service.py`** — CRUD for projects, scoped so a user can only touch their own (unowned project access returns 404, not 403).
- **`backend/api/dependencies/auth.py`** — the `get_current_user` guard; every route except register/login requires a valid bearer token.
- **`backend/api/routes/auth.py`** + **`backend/api/controllers/auth_controller.py`** — `/api/auth/register`, `/login`, `/logout`, `/me`.
- **`backend/api/routes/projects.py`** + **`backend/api/controllers/project_controller.py`** — `/api/projects` CRUD.

### Unified UML JSON schema (done — Milestone 3)
- **`backend/schemas/uml.py`** — `UmlDocument`, `UmlClass`, `Attribute`, `Method`, `Relationship`. Validation (e.g. a relationship must point at real class IDs) lives directly on `UmlDocument` as a Pydantic `model_validator` — there's no separate `validators.py` file.

### Image → JSON pipeline (done — Milestone 2)
- **`backend/cv/preprocessor.py`** — grayscale/threshold/denoise/contour prep (OpenCV).
- **`backend/cv/shape_detector.py`** — finds class-box rectangles in the image.
- **`backend/ocr/extractor.py`** — runs Tesseract OCR on each detected box.
- **`backend/parser/text_parser.py`** — turns raw OCR text into structured attribute/method dicts (handles `+`/`-`/`#` visibility, type annotations, OCR typos).
- **`backend/services/image_service.py`** — orchestrates cv → ocr → parser → schema, the whole image-to-JSON pipeline.
- **`backend/api/routes/image.py`** + **`image_controller.py`** — `/api/image-to-json`.

### Code generation (done — Milestone 4)
- **`backend/generator/language_maps/{python,java,javascript}.py`** — maps schema types (`String`, `int`, etc.) to each language's real types.
- **`backend/generator/templates/{python,java,javascript}/class.j2`** — Jinja2 templates, one class per file, method bodies are stubs only (never fabricated logic).
- **`backend/generator/registry.py`** — maps a language name to its type-map + template folder.
- **`backend/services/codegen_service.py`** — orchestrates schema → generator.
- **`backend/api/routes/codegen.py`** + **`codegen_controller.py`** — `/api/generate-code`, `/api/languages`, `/api/templates`.

### HTTP boundary models
- **`backend/models/requests.py`** / **`responses.py`** — request/response Pydantic shapes for the HTTP layer (separate from the schema layer). Includes `ReverseRequest`/`ReverseResponse` and `JsonToMermaidRequest`/`MermaidResponse` — defined already, but **unused**, waiting on Milestones 5/6.

### Not built yet (empty directories)
- **`backend/reverse/`** — should hold Python/Java/JavaScript AST parsers (`parse(source) -> UmlDocument`) and a `registry.py`. Currently empty.
- **`backend/mermaid/`** — should turn a `UmlDocument` into Mermaid `classDiagram` text. Currently empty.
- No `/api/reverse` or `/api/json-to-mermaid` route exists in `main.py` yet.

## 4. File-by-file: Frontend

### Pages (`frontend/src/pages/`)
- **`HomePage.tsx`** — marketing/landing page at `/`.
- **`LoginPage.tsx` / `SignupPage.tsx`** — auth forms.
- **`DashboardPage.tsx`** — lists the logged-in user's projects (create/rename/delete).
- **`EditorPage.tsx`** — the actual diagram canvas for one project; loads/saves its diagram via the projects API.

### Routing & Auth state
- **`App.tsx`** — top-level router (`react-router-dom`), wires up all pages.
- **`context/AuthContext.tsx`** — holds the JWT session, persisted across reloads.
- **`components/routing/ProtectedRoute.tsx`** — redirects to login if there's no valid session.

### Canvas editor (Milestone 1 — mostly done)
- **`components/canvas/{Canvas,Grid,SelectionOverlay,ShapeRenderer}.tsx`** — infinite pan/zoom canvas, grid+snap, generic shape rendering, selection box.
- **`components/uml/UmlClassBox.tsx`** — the three-compartment class box (name/attributes/methods), plus `AttributeRow.tsx`, `MethodRow.tsx`, `ModifierChip.tsx`.
- **`components/uml/RelationshipEdge.tsx`**, `RelationshipMarkerDefs.tsx`, `relationshipStyles.ts` — the five relationship line types.
- **`components/uml/umlClassSerializer.ts`** — converts canvas state ⇄ Unified UML JSON shape.
- **`components/toolbar/*`** — tool picker, relationship picker, zoom controls, PNG export button, image-upload modal, code-gen panel + viewer.
- **`hooks/useDiagram.ts`** — canonical diagram state (all canvas state flows through this, per CLAUDE.md rules).
- **`hooks/{useCanvas,useSelection,useKeyboardShortcuts,useTheme,useScrollReveal}.ts`** — supporting interaction hooks.
- **`utils/{geometry,id,pngExport,constants}.ts`** — math helpers, ID generation, PNG export logic.

### API client (`frontend/src/api/`)
- **`client.ts`** — shared fetch wrapper (attaches bearer token).
- **`authApi.ts`, `projectsApi.ts`, `imageApi.ts`, `codegenApi.ts`** — one file per backend route group. (No `mermaidApi.ts`/`reverseApi.ts` yet — nothing to call.)

### Not built yet
- No Mermaid rendering/preview panel (waiting on backend Milestone 6).
- No reverse-engineering UI (paste-code-in flow) (waiting on Milestone 5).
- No activity-diagram UI (waiting on Milestone 9).

## 6. What's left, in order

1. **Reverse Engineering (M5)** — write a Python AST parser first (`ast` module, stdlib), get `parse(source) -> UmlDocument` working and tested, then do the same for Java and JavaScript. Wire up `/api/reverse`.
2. **Mermaid generation (M6)** — turn a `UmlDocument` into Mermaid `classDiagram` text, add `/api/json-to-mermaid`, add a preview panel on the frontend. Later extension: also pull control-flow out of parsed functions and render it as a Mermaid flowchart (activity diagram from code).
3. **Full integration tests (M7)** — once 5 and 6 exist, write an end-to-end reverse-pipeline test (source → JSON → Mermaid) to match the forward-pipeline one that already exists.
4. **Activity Diagram forward pipeline (M9)** — the biggest remaining feature: upload a hand-drawn flowchart image, detect start/end/action/decision shapes, OCR the labels, reconstruct real `if`/`while` structure, and generate a standalone function (with the same "never fabricate logic" scaffold rule as the class-diagram generator). Fully designed in `CLAUDE.md` but zero code written.
